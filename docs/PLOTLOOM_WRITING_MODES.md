# 小说与短剧：入口、参数和生成格式

2026-10-29后端进一步拆分为独立的`studio_novel.py`和`studio_drama.py`，兼容入口仍使用`studio_writing.py`路由。当前小说章节上下文、跨任务摘要及表达规则详见[PLOTLOOM_NOVEL_BACKEND.md](PLOTLOOM_NOVEL_BACKEND.md)；下文保留此前类型修复的历史依据。

## 参考资料与设计依据

- [Final Draft：Screenplay Formatting and Elements](https://www.finaldraft.com/learn/screenplay-formatting-elements/) 将剧本组织为场景标题、动作、人物和对白等元素。Plotloom因此为剧本保留可拍摄的分场输出，并提供画幅、单集时长、场景密度和集尾钩子设置。
- [Reedsy：Point of View](https://reedsy.com/blog/guide/point-of-view/) 说明第一人称、第三人称有限、全知及多视角如何影响叙述范围和阅读体验。Plotloom因此为小说提供独立的叙事视角、文风和节奏设置，正文使用连续叙事、人物心理与自然对白。

上述是公开资料支持的创作差异；具体字段、枚举、默认值及题材列表是本项目的产品设计，没有宣称复制其他平台的完整表单，也没有抓取登录后的作者后台。

## 排查发现

2026-10-26只读检查线上9份作品时，发现5份标为novel的记录中，有3份mode仍为“新建剧本”（含两份已归档验收作品）。这是旧WorkInput的通用默认值；旧表单同时允许在小说入口切换内容类型。两者使入口名称、content_type和mode可能不一致。仅凭记录不能断言用户反馈的具体哪次生成受此影响，但这些冲突元数据确实会进入原生成上下文。

持久工作者原小说系统提示只有“你是中文小说家”，正文格式仅一句叙述要求，没有拒收场次剧本的校验；不同路径还维护了各自的提示词。该设计无法保证模型不会沿用原稿或参考素材的剧本格式。

## 修复后的行为

| 项目 | 小说 | 短剧 |
| --- | --- | --- |
| 入口 | 小说入口固定为novel，不提供类型切换 | 剧本入口固定为short_drama，不提供类型切换 |
| 专属设置 | 连载／短中篇、叙事视角、文风、节奏 | 竖屏／横屏、单集时长、场景密度、集尾钩子 |
| 默认字数 | 每章2000，允许300至6000 | 新建页每集800，允许300至3000 |
| 题材示例 | 都市日常、现代／古代言情、悬疑推理、东方玄幻、仙侠、科幻末世、历史架空等 | 都市、甜宠、悬疑、古装、家庭、职场、轻喜剧、玄幻等 |
| 人物与大纲 | 人物成长与视角、章节事件与信息铺垫 | 可表演行为与对白口吻、单集冲突与反转钩子 |
| 正文 | 连续小说叙事、心理、动作和引号对白 | 场次、地点、日夜内外景、动作与角色对白 |

- `content_type`为权威类型，mode按类型规范化；旧记录生成时在快照副本中修正相互矛盾的mode，不批量改写用户历史记录或正文。
- 已创建作品不能通过更新接口更改content_type。类型不匹配的参考素材在创建时拒绝。旧浏览器草稿如与入口类型不同，保留单独备份供导出，不静默覆盖或转成另一种作品。
- 专属参数跟随作品保存、备份、导入、生成快照与灵感分析，两个类型不接受对方的参数。既有作品缺少新字段时使用对应默认值；用户已经设置的历史字数不会被强制改写。
- 两条生成路径共用`agent/studio_writing.py`中的角色、分步指令及正文格式检查。小说若出现明确场次标题或高密度角色冒号台词清单，会标记失败；短剧缺少明确场次同样标记失败。自然小说中偶尔提及“剧本”或“第一场比赛”不会仅因关键词被拒收。
- 格式不匹配时保留作品，不存为可采纳成功稿，不静默重试付费调用；用户可调整素材后主动重新生成。此检查针对明显格式错误，不能代替完整文学质量评审。

## 验证

离线覆盖模式规范化、旧快照无损处理、不可变作品类型、参数范围与隔离、备份保留、两条生成路径的格式拒收与有效正文采纳。前端使用真实组件的服务端渲染检查类型下拉框已移除，小说／剧本只显示对应参数、范围和默认值。真实模型与线上验收结果另见发布记录。
