# Plotloom 中文创作工作台：本机使用与验证

当前工作台包含剧本、小说、灵感创作、作品独立世界、语料参考和持久生成队列。本机开发与线上发布分开；发布记录见 `PLOTLOOM_DEPLOYMENT.md`。本文于2026-10-29更新，以当前代码为准。中文版运行源码58dbd41（移除大纲起承转合导航，保留正文JSON交付修复、一键生成及新建世界AI入口），小说独立写作与自然分段／视角／证据／状态规则已上线；导入改为顶部弹窗、世界管理集中工具栏、模型信息并入我的空间。编辑器新增“参数与世界”形成五页导航，保留原站页头与侧栏；四类写作及作品世界生成直接填入对应新版编辑区，大纲同时生成粗纲与分集／章纲，粗纲支持临时流式预览。Git后续并行提交不代表已经上线，应核对实际RELEASE_COMMIT。验收边界见 `PLOTLOOM_EDITOR_DEPLOY_HANDOFF.md` 和 `AGENT.md` 最新记录。

## 本机启动

需要 Python 3.10+、Node 24+。Python 依赖见根目录 `requirements.txt`，前端依赖在 `ai-website-cloner-template/`。模型配置放 Git 忽略的 `data/llm_config.json` 或根目录 `.env`，不要提交密钥；网页模型信息只读。

由用户自行在三个终端启动。Windows PowerShell 示例（前两个终端均位于实际仓库 `duanju-agent/`）：

```powershell
# 终端一：独立中文 API，避免启动旧站的采集和续写调度器
.venv\Scripts\python.exe -m uvicorn studio_main:app --host 127.0.0.1 --port 8765
```

```powershell
# 终端二：正文及灵感任务共用的独立工作进程
.venv\Scripts\python.exe -m agent.studio_worker
```

```powershell
# 终端三：网页
cd ai-website-cloner-template
npm run dev -- --webpack --hostname 127.0.0.1 --port 3000
```

macOS/Linux 使用所配虚拟环境的 `python` 运行相同模块。自行打开 `http://127.0.0.1:3000`。前端默认代理后端8765；可通过前端 `.env.example` 中的 `DUANJU_BACKEND_URL` 修改。仅启动 API 会接收并保存任务，但生成会停在“排队中”；必须同时运行工作进程。不要同时运行两个指向同一数据库的工作者。

API与工作者默认使用同一个 `data/studio/studio.sqlite3`。如设置 `DUANJU_STUDIO_DB`，两个终端必须指向同一文件。模型配置与实际运行数据不会通过 GitHub 同步。

## 灵感创作

1. 在“剧本创作”或“小说创作”的新建页，点击“灵感创作”。旧“灵感策划”入口也会打开此弹窗。
2. 用自然语言描述故事想法，可补充目标受众、题材、核心设定与风格偏好。点击“生成三个参考方案”。剧本与小说使用不同的策划提示。
3. 三个方案分别显示名称、卖点与故事方向。每个方案都可手动编辑并保存，也可输入修改要求，让 AI 只调整这一个方案。未保存的编辑与修改要求在此浏览器保留；版本变化时不把旧输入覆盖到新方案。
4. 点击某个方案的“选择并解析设定”，弹窗会回到上方显示任务进度。系统只分析所选方案，生成名称、故事想法、受众、计划集／章数、字数、题材、核心设定、风格、亮点及结构化世界观；完成后进入单独的结果视图，可返回三个方案或再次查看已有结果。
5. 查看解析结果，确认回填创作表单。新建时此步骤尚未创建作品，也未生成正文；已有作品也可在设定页打开灵感，只更新设定，保留原人物、大纲和正文。题材、核心设定和风格以标签编辑，保留解析数组边界，标签内部逗号不会被拆分。新建表单有回填前浏览器备份，可点击“恢复回填前的表单”；已有作品提供本轮恢复设定按钮。改编／改写原始素材另行保留。
6. 回填后在“故事梗概”检查故事与创意字段，在“参数与世界”检查数量、专属参数和世界观，再通过顶部五页导航填写人物、大纲和正文。选择“保存全部内容，创建作品”仅保存草稿；写作页点击AI生成会先保存输入，再将生成内容填入对应编辑区。已手写的人物、大纲和正文不会因灵感回填而清空。

灵感草稿与作品分开保存，关闭窗口不会取消服务端任务。重开弹窗可读取最近草稿，也可手动刷新方案。失败或执行进程中断时保留已有方案，由用户主动重试；中断调用可能已经计费，不会静默重发。所有灵感操作与正文生成共用全站最多3个同时执行的模型请求、最多10个新排队任务，重复请求键在各独立空间内复用原任务。

如果旧版已回填草稿因项目内逗号而提示标签超限，原有分隔边界无法从草稿文本可靠推断。可在同一浏览器重新打开仍保存的灵感解析结果并确认回填，再检查其他表单内容；旧表单会保留回填前备份。也可手动整理标签。普通旧草稿继续按逗号分隔。

## 剧本与小说创作

- 新建与编辑在原站页头及侧栏右侧共用截图风格深色界面，顶部作品名可编辑，五页导航固定在网站页头下方：“故事梗概、参数与世界、人物档案／小传、章节／分集大纲、小说／剧本正文”。点击或左右键、Home／End切换，白底表示当前页；手机页签横向滚动，选择及窗口变窄后当前页签保持可见。灵感仅在梗概页，原四类AI生成动作不增加参数阶段。
- 新建页五页都可手动填写，不必先创建作品。名称、参数、世界观与写作内容一起保存；浏览器草稿记录当前页和正文编号，`step=settings`可恢复参数页。新建参数页提供保存创建，创建后的该页提供AI完善世界；其余写作页点击AI生成时先创建保存，再只提交当前动作及选中集／章。请求失败不重复创建或自动重发，查询参数不启动模型。
- 人物采用左侧详情、右侧角色网格，支持新增、选择、确认删除和全文编辑；详情含姓名、可自定义定位、可未知的年龄、性格标签、背景、人物关系。窄屏角色卡横向排列在详情上方。旧文字只读打开不改稿，无法识别的经历保留在背景并可全文整理，不凭空推断身份和年龄。
- 四步生成完成后经服务器版本校验直接填入当前作品并保存：梗概进入设定表单、人物进入角色卡片、大纲进入对应章／集卡片、正文进入对应正文编辑器。刷新可恢复；正文保留自定义标题和其他单元。生成状态仅用紧凑文字及必要的停止／继续操作，不再显示旧“生成任务与候选稿”面板、绿色进度条或常规提交蓝色横条。AI人物前言保留在全文，不冒充额外人物。
- 人物仍保存在原characters纯文本字段。卡片编辑输出可读的【人物：姓名】／标签字段／【人物结束】块，多行字段缩进以保留字面标签与末尾换行；未修改的旧人物块保留原文。新AI提示使用相同字段标签，小说背景仍要求欲望／内在冲突／成长弧，剧本背景仍要求可表演行动／对白口吻；接口和数据库无结构迁移。
- 支持分步生成和一键生成设定、人物、大纲及全部计划正文（1至200单元）。新建与已有作品共用工具栏最左侧“一键生成全部”，替换原撤销／重做两个图标；所有五页均可进入。新建时先保存完整草稿，再只提交一个mode=all持久任务；已有作品先保存再提交，沿用进度、停止／继续及版本保护。请求未确认不会重复创建作品或自动重发生成。
- 新建页的类型由左侧入口固定，不再重复选择。小说提供作品形态、叙事视角、文风、节奏和独立主分类，默认每章2000字；剧本提供画幅、单集时长、场景密度和集尾钩子，默认每集800字。小说上限6000字，剧本上限3000字。细节与资料来源见`PLOTLOOM_WRITING_MODES.md`。
- 两条生成路径按内容类型规范化旧mode；小说正文的场记／台词清单、缺少场次的剧本会标记失败而不覆盖作品。旧浏览器中的另一类型草稿保留可导出备份，不混入当前入口。
- 生成前先保存编辑，结果仍持久保存为独立生成记录。单独生成及一键全部生成均自动回填已完成部分，后台采纳接口的`ready_only`在同一事务校验版本并保证幂等；`adoption_revision`跟踪已应用批次。一键任务不会等全部正文完成才显示内容。生成期间有手动或外部修改时停止自动覆盖，可在同一新版编辑器只读查看生成稿或导出。回填响应丢失只重读保存结果，不重新付费生成；失败不返回模板假结果。
- “保存并进入下一步”衔接编辑；正文通过目录切换、新建集／章及续写。计划数量不能小于已有正文的最大编号，无效数字不得保存或触发生成。大纲可折叠粗纲并添加逐集／章分纲，全部条目在完整宽度内显示；明确“第N章：／第N集：”标题后的多段内容完整进入相应卡片，不推断阶段。无法可靠拆分的旧稿完整保留在粗纲，提供全文编辑。卡片仅编辑时输出可逆文本，不迁移数据库。
- 点击AI生成大纲时一次调用同时生成全篇粗纲与所有计划集／章纲，分别填入粗纲和单元卡片。粗纲由服务端流式接收，经现有任务轮询在粗纲框临时预览；完整输出须同时通过粗纲及有序编号校验才写入结果、按版本回填作品。新任务标记`outline_format=combined-v1`，任务详情追加`partial_outline`；旧任务兼容。临时预览不写作品、不参与采纳，不显示模型推理，手写或外部修改阻止覆盖；截断、断流、限流失败保留原稿，零自动付费重试。
- 新建表单在此浏览器保留草稿；已有作品自动保存，另有手动保存、离页保护及冲突备份。同一空间的多个标签页修改后，新版本不能被旧版本静默覆盖。
- “参数与世界”采用创作参数和作品世界两张深色卡片。数量／字数、主分类和类型专属参数集中编辑；世界观概述只在此出现一次，详细世界按六类折叠分组。世界库复制后成为作品独立副本，可另存、导出和AI完善，不影响原件或其他作品。梗概只保留受众、题材标签、核心设定、风格、亮点、梗概及素材。
- 支持 TXT 导出、完整 JSON 备份导入、作品复制、归档恢复、浏览器旧草稿迁移及明确标记为中国市场的旧站历史导入。正文可导出Word兼容HTML `.doc`（不是原生`.docx`），用户文字先转义。手动引用的语料保留来源，并与内容类型匹配。
- “我的作品”统一展示小说、剧本与已归档作品，支持名称搜索、类型／状态筛选和最近更新／最近创建／名称排序。卡片显示正文进度、更新时间及复制／归档／恢复／删除操作；创建入口保留在侧栏，历史导入默认收起。
- 删除须确认，可先下载完整备份。删除正文、作品世界副本、旧候选与生成记录，保留世界库原件及其他作品；进行中的任务或旧版本删除请求会被拒绝。删除后不能直接恢复，可导入事先下载的备份。
- 页面侧栏独立加载，编辑页先显示作品，世界库、模型信息和旧候选独立读取。作品列表请求`/api/studio/works?view=summary`仅传摘要；返回作品库时先显示内存中的上次列表，再重新核对服务器。归档接口`PATCH /api/studio/works/{id}/archive`及删除接口`DELETE /api/studio/works/{id}?revision=…`均校验版本；原完整列表接口保持兼容。

## 入口与边界

- 前端 `ai-website-cloner-template/` 通过 `/api/backend/studio/*` 代理访问 `/api/studio/*`。
- 推荐本机使用 `studio_main:app`；原 `main:app` 也挂载工作台与队列路由，其旧 `/generate` 入口仍保留兼容行为。使用旧入口时按需关闭 `DUANJU_SCHEDULER_ENABLED` 和 `DUANJU_WRITER_AUTO_RESUME_ENABLED`。
- SQLite 增量增加灵感会话与任务表，不删除旧作品、候选和队列。工作者独占锁，只有取得锁的工作者恢复中断任务。
- 工作台目前面向中文、中国市场，免注册按浏览器独立空间隔离作品、世界、灵感和任务；身份保存在HttpOnly Cookie中。更换浏览器或清除网站数据前须导出备份。同一浏览器／配置内的标签页共用一个空间，不是账号登录，也不隔离共用此浏览器的人。日本站保持原市场边界。
- 全站使用原有单一模型Key，最多3个请求同时执行；不同空间优先分配空位，一键长任务完成一步后让出名额。只有一个空间有任务时，可同时生成不同作品或灵感任务，使用全部3个名额；同一作品的章节保持顺序，避免前文衔接丢失。遇到模型限流，暂缓新调度30秒，失败步骤仅主动重试。
- 原共享作品不分配给第一个访问者。维护者准备一次性恢复码后，原用户在“我的空间 → 恢复以前的共享作品”领取，原稿、世界、候选和任务完整转入当前空间；没有恢复码的访客无法读取旧共享记录。操作说明见`PLOTLOOM_CONCURRENCY_AND_SPACES.md`。
- 世界模块与草稿规范来源见 `third_party/storyforge/README.md`，不宣称完整嵌入 StoryForge。
- 一键长篇生成的技术流程可测试；文学质量、内容一致性和真实模型稳定性仍需人工审阅。上下文超预算明确失败，不截去世界规则。
