# Plotloom 网页会员支付方案分析

核验日期：2026-11-04。本文为方案分析，未选择渠道、设置价格、创建商户、提交资质或接入支付。

## 建议的第一阶段

如果首先面向中国大陆用户收取人民币，优先评估支付宝网页支付与微信支付：电脑端使用支付宝网站收银台和微信 Native 扫码；手机浏览器按渠道实际权限接支付宝移动网站支付、微信 H5 或微信内 JSAPI。各场景的资质、网站、商户和产品权限须以官方审核及商户合同为准。

- [支付宝网页／移动应用接入](https://open.alipay.com/module/webApp)：官方提供网页和移动应用支付接入，需创建应用、配置密钥和提交审核。
- [微信 Native 支付产品](https://pay.wechatpay.cn/doc/v3/merchant/4012791874)和[接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015614538)：电脑网页扫码，申请与商户主体、认证后的公众账号或其他支持的 AppID 及其绑定有关。手机网页与微信内支付是不同场景，需分别确认权限。
- [微信 PC 网站申请指引](https://pay.wechatpay.cn/static/applyment_guide/applyment_detail_website.shtml)列出主体和材料示例；页面所述费率为一般范围，实际类目、合同、结算账户和费率以渠道签约结果为准。

先实现**一次性购买月卡／年卡、到期由用户主动续费**，不默认开通自动扣款。日历月／年的权益叠加可复用 `studio_membership.grant`，但必须先有可靠的支付订单和验签，不可直接信任前端。自动续费需要另行选择渠道能力，并单独处理签约、取消、续费失败、退款和用户告知。

## 台湾与其他地区

- 台湾可调研[绿界 ECPay](https://developers.ecpay.com.tw/2860/)：官方列出信用卡一次付款、定期定额等方式，具体可用方式及收款资质以商户审核和合同为准。
- 拥有 Stripe 支持地区合法经营主体的情况下，可评估 Stripe Checkout；[Stripe 目前公布的商家支持地区](https://stripe.com/global)包含香港、日本等，名单中未列中国大陆或台湾。用户所在地和商家主体所在地是不同问题，不能仅凭用户位于台湾就认定能够开通。
- [PayPal Subscriptions](https://developer.paypal.com/platforms/subscriptions/overview/) 提供订阅计划和周期收费，可作海外备选，需核对实际商家所在地及账户权限。

是否需要台湾本地收款、货币、发票与适用规则，取决于实际经营主体及客户市场；不能在主体未明确时承诺能够开通某渠道或使用某费率。

## 技术接入轮廓

1. 由服务器保存商品、币种、价格及订单快照；已登录账号选择月卡／年卡，服务器创建与账号绑定的订单并请求渠道支付。页面状态不能作为成交依据。
2. 收到支付渠道服务端通知后验证签名、商户／应用、订单号、币种、金额和成功状态；使用订单号和渠道交易号约束重复处理，在同一数据库事务更新订单并通过稳定唯一 grant_id 赋予对应会员。未收到通知或结果不明时通过渠道查询并对账。见[微信回调与查单指引](https://pay.wechatpay.cn/doc/v3/partner/4012082568)和[Stripe 服务端事件说明](https://docs.stripe.com/payments/existing-customers?platform=web&ui=stripe-hosted)。
3. 支付回调是渠道服务器发来的请求；当前 `/api/studio` 的账号 Cookie 和同源校验不能直接作为回调认证。应新增独立的服务端回调入口，按渠道签名校验，并同步审查生产代理路由；不能仅为通行关闭账号接口的保护。
4. 保存订单、支付事件、退款和审计记录，支持去重、失败重试、异常告警、定期对账和退款处理。退款与权益回收应明确业务规则；已有后续赠送或永久 VIP 时不能简单清空所有权益。
5. 用渠道沙箱与模拟通知验证重复、乱序、超时、金额不符、伪造通知、退款和并发等情况；正式商户开通及小额真实支付需单独安排。不得保存银行卡敏感数据或把密钥写进代码与 Git。

## 需要确定

首发市场及收款币种、商户主体所在地及资质、月卡／年卡价格、是否自动续费、退款与发票规则，以及先接入支付宝还是微信。现有账号为永久开发测试 VIP，付费用户与测试权益需在管理记录中清晰区分。
