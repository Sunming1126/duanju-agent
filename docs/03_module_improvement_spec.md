# 平台四大模块改进规格说明书（v0.6）

> 范围：知识图谱 / 灵感索引 / 钩子工作台 / 类别管理
> 依据：2026-09-23 现状评估（数据规模：图谱 199 实体 295 关系；钩子库 35 条其中 28 条待审核且类别失衡；类别 29 个）

---

## 0. 现状评估结论

### 模块A 知识图谱（graph.js + /api/graph）
已有：Canvas 力导向、缩放/拖拽/悬停/详情面板/最短路径/类型聚类/过滤/知识抽取。
**问题**：
- A1 无统计概览：进页面看不到实体/关系/待审核规模与最近抽取时间（只有一行查询 meta）。
- A2 搜索无定位：搜索后仅重载子图，命中节点不居中、不高亮，用户不知道"搜到了哪"。
- A3 邻居跳转缺陷：详情面板点击邻居时，若该邻居类型被类型过滤排除（不在当前 nodes），点击无任何反应。

### 模块B 灵感索引（app.js + /api/inspire）
已有：BM25 + 题材/情感/标签过滤检索、关联推荐（图谱关联度+互补标签）、双人对比。
**问题**：
- B1 定位模糊：本质是"语料检索器"，不产出灵感；与工作台"知识检索"能力重叠。
- B2 无关键词时仅按热度取前 N 条，没有灵感价值。
- B3 平台已有资产（钩子库/节拍库/反转套路/题材维度）完全没有接入灵感流程。
- B4 空结果无引导，用户不知道下一步做什么。

### 模块C 钩子工作台（hooks.js + /api/hooks）
已有：CRUD、三属性标准（位置×机制×强度）、版本管理、审核状态机、规则抽取、结构模板、小说转化。
**问题**：
- C1 内容少且失衡：仅 35 条，28 条待审核淹没列表；金句/标题/危机钩各只有 1 条，已通过仅 7 条。
- C2 无统计概览：看不到类别分布/通过率/强度分布。
- C3 三属性标准没有闭环：没有"开场+中段+结尾"组合视角，也没有"把钩子用于生成"的出口——钩子库是孤岛。
- C4 待审核无批量操作，28 条逐条点效率低。

### 模块D 类别管理（cats.js + /api/categories）
已有：4 维度体系、CRUD、归档、related_ids 双向同步、扩展接口位说明。
**问题**：
- D1 无使用统计：看不出每个类别挂接了多少内容（图谱实体/语料/钩子），类别是否"有用"不可见。
- D2 右侧"扩展接口位"是开发向信息，对使用者无价值。
- D3 点击类别看不到挂接的具体内容清单。

## 1. 知识图谱改进

### 目标
让图谱页具备"规模可感知、搜索可定位、跳转不失效"的完整体验。

### 实现方案
| # | 项 | 方案 |
|---|---|---|
| A1 | 统计概览条 | 画布顶部新增 stats 行：实体/关系/待审核/平均度/最近抽取。数据源复用 `GET /api/stats`（已含 graph 块），activate 时加载 |
| A2 | 搜索定位 | `load()` 完成后若 q 非空：命中节点全部加入 hlNodes 高亮，首个命中 `centerOn(node)` 平滑居中（scale 至 1.4） |
| A3 | 邻居跳转修复 | `select()` 中目标节点不在当前 nodes 时：自动勾选其类型 → `load()` → load 完成后定位并选中该节点（通过 `_pendingSelect` 变量跨加载传递） |

### 验收标准
- [ ] 打开图谱页顶部显示"实体 199 · 关系 295 · 待审核 N · 最近抽取时间"
- [ ] 搜索"龙王"→ 画布高亮命中节点并居中首个命中
- [ ] 过滤只留一种类型 → 点击详情面板中其他类型邻居 → 自动恢复该类型显示并选中目标节点

## 2. 灵感索引重构（→ 灵感工作台）

### 目标
从"语料检索器"升级为"灵感发生器"：抽卡产生创意种子 → 一键进工作台；检索降级为"找参考"的辅助手段。

### 核心价值定义
- **抽卡**（灵感发生）：题材 × 情绪 × 钩子机制 × 节拍套路 随机组合，产出可直接执行的创意种子。
- **找参考**（灵感验证）：保留原检索/关联/对比能力，用于验证创意是否撞车、找同类参考。

### 实现方案
| # | 项 | 方案 |
|---|---|---|
| B1 | 新端点 `GET /api/inspire/spark` | 组合生成：题材（fallback.BEAT_LIB 8 类 ∪ 语料 genre）× 情绪词 × 钩子机制 × 主角人设模板 × 片名模板 → 返回 {title, genre, hero, logline, open_hook, beats[6], tags}。open_hook 优先从已通过钩子库抽真实钩子，不足时用 fallback.HOOKS 模板 |
| B2 | 前端抽卡区 | 结果区顶部固定"灵感抽卡"卡：显示创意种子全字段 + 「🎲 再抽一张」「▶ 填入工作台生成」 |
| B3 | 填入工作台 | `fillStudio(spark)`：切到 studio 视图并填充 题材/创意/主角 三个表单，toast 提示 |
| B4 | 空态引导 | 检索无结果时显示"换个关键词，或点上方 🎲 抽一张灵感卡" |
| B5 | 文案调整 | 左栏标题"多维检索"→"找参考"；hint 说明改为抽卡优先 |

### 验收标准
- [ ] 点抽卡返回完整种子卡（含一句话创意/开场钩子/6 节拍/标签），连续抽结果不同
- [ ] 「填入工作台」后自动切换到工作台且三个表单已被填充
- [ ] 空关键词+空过滤检索 → 显示引导文案而非空白
- [ ] /api/inspire/spark 响应 ≤ 100ms

## 3. 钩子工作台扩充

### 目标
把钩子库从"存条目的孤岛"变成"可组合、可消费的生产资料"。

### 实现方案
| # | 项 | 方案 |
|---|---|---|
| C1 | 内容扩充 | hooks.py 新增 `ensure_seed()`：内置 32 条扩充种子（7 类别均衡，全部 approved、真实可拍文本、合理 tags），按 id 前缀幂等（已存在不重复添加），main.py lifespan 调用。扩充后库内 ≈67 条、每类 approved ≥5 |
| C2 | 统计概览条 | 左栏顶部：总数/待审/已通过 + 7 类别 chip（点击=按类别过滤）。前端从 `/api/hooks` 全量数据现算，不加后端 |
| C3 | 钩子配方 tab | 右侧新增第 4 个 tab「钩子配方」：开场/中段/结尾三行，每行可选机制过滤，「🎲 抽一组」从 approved 池各抽 1 条 → 三钩连排预览 + 「▶ 用这组钩子去生成」（拼接为创意填入工作台，genre 从钩子 tags 推断） |
| C4 | 消费出口 | 编辑器底部加「▶ 用此钩子生成」：以钩子文本+类别填入工作台 |
| C5 | 批量审核 | 待审核 tab 加「✓ 全部通过」；后端新增 `POST /api/hooks/bulk_review {ids?, all_pending?, approved}`，同步图谱置信度 |

### 验收标准
- [ ] 重启服务后钩子库 ≥60 条，7 类别每类 approved ≥5 条
- [ ] 概览条数字与库一致，类别 chip 可过滤
- [ ] 配方 tab 抽出开场/中段/结尾 3 条组合，一键填入工作台并自动切视图
- [ ] 待审核 tab「全部通过」后 pending 清零、图谱中对应节点 review 变 auto_pass
- [ ] 已通过的 7 类别钩子在配方池中可被抽到

## 4. 类别管理价值提升

### 目标
让类别管理从"配置 CRUD"变成"内容地图"：每个类别能看到它挂接了多少、挂了什么、哪里空转。

### 实现方案
| # | 项 | 方案 |
|---|---|---|
| D1 | 使用统计 | `GET /api/categories` 响应新增 `usage: {cid: {graph, corpus, hooks}}`：图谱实体按 category_ids 计数；语料按 genre 含类别名计数；钩子按 category 名计数。在 main.py 端点层组装（categories.py 保持存储纯净） |
| D2 | 列表徽标 | 类别行显示 `图N · 料N · 钩N` 徽标，0 挂接置灰 |
| D3 | 挂接内容清单 | 选中类别后编辑器下方新增「挂接内容」：图谱实体名前 8 条（点击跳图谱并定位）+ 语料名前 5 条 |
| D4 | 右栏替换 | 「扩展接口位」→「类别×内容交叉统计」：按维度汇总挂接总量排行 + 0 挂接类别提醒清单 |

### 验收标准
- [ ] 每个类别行显示三项挂接数，与实际数据一致（抽查 2 个类别）
- [ ] 选中"题材:逆袭"能看到挂接的图谱实体清单，点击实体跳转图谱页并定位
- [ ] 右栏显示各维度挂接排行与空转类别提醒
- [ ] 归档类别同样显示统计（保留历史可见性）
