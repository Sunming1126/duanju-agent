# 三请求并发与浏览器独立空间

## 使用方式

继续使用服务器原有模型Key，没有添加另外两份测试凭据。全站最多3个模型请求同时执行，灵感与正文共用预算。只有一位访客有任务时，可以同时处理3部不同作品／灵感；多位访客等待时，优先分配给执行中任务较少、较久未获得执行机会的空间。

同一作品只有一个进行中的任务，各集／章按顺序使用前文、事实摘要和世界规则。一键生成每完成一步即保存并重新参与调度，其他访客不必等整本生成结束。停止、失败继续、旧版本阻止采纳、显式采纳和完整备份保持原行为。收到模型429后，暂停新的调度30秒，失败调用没有自动付费重试。

## 简单隔离的范围

首次使用时自动建立免注册的浏览器空间。作品、世界、灵感、候选和生成任务均校验归属，读取、导出、修改、删除、复制、停止、续跑和采纳都不能跨空间。官方样例和语料参考保持公开。

同一浏览器配置的标签页共享空间；不同浏览器／配置各自独立。这不是账号登录，不能区分共同使用同一个浏览器的人，也没有用户名密码或跨设备登录。清理网站数据或更换浏览器前，请导出完整作品备份。

身份是服务端生成的随机Cookie，仅存储凭据摘要，Cookie设置HttpOnly、SameSite=Lax，HTTPS下使用Secure。空间编号不是凭据，不能用编号或自定义请求头伪造身份。私有接口响应禁止缓存，幂等键及浏览器旧稿ID按空间隔离。

前端并行请求共用一次`GET /api/studio/session`初始化，支持Web Locks的浏览器还会协调多个标签页首次访问。后续请求发送同源Cookie，未登录／失效的私有请求返回401，其他空间的记录返回404。服务端身份校验使用同一依赖同时保护studio_main和旧main的studio路由；CLI与独立工作者作为可信内部调用访问数据。

写操作校验浏览器Origin，默认允许当前站点和正式域名`https://jubencn.onesay.top`；在其他正式域名部署时设置`PLOTLOOM_PUBLIC_ORIGIN`。公网代理转发真实客户端IP后，也能识别正式页面的同源保存请求；任意客户端伪造的代理头不能放行外站Origin。

## 原共享作品的恢复

现有数据保留原ID、正文、版本和时间。没有归属的数据作为待领取旧空间保留，新访客不能直接访问，也不会自动成为旧作品所有者。

发布入口在SQLite备份之后为第一次隔离上线准备一次性恢复码。恢复码仅保存在服务器`/opt/plotloom-cn/shared/data/studio/legacy-claim-code.txt`，权限0600；数据库只保存摘要。发布日志只显示文件路径，不显示恢复码。

维护者也可以在服务器以服务用户手动准备（文件已存在时拒绝覆盖）：

```bash
cd /opt/plotloom-cn/current
/opt/plotloom-cn/venv/bin/python tools/studio_legacy_claim.py --db /opt/plotloom-cn/shared/data/studio/studio.sqlite3
```

将恢复码私下交给原站点所有者，其在目标浏览器“我的空间 → 恢复以前的共享作品”填写一次。旧作品、世界、候选、任务和灵感记录在一个事务内转入该空间，版本和正文不改，并授予旧站中文历史导入权限。恢复码用过即失效，不写进Git、工单、聊天或公开链接。领取前请确认使用希望长期保留的浏览器。

## 发布与回滚

新版本继续使用共享SQLite与单个独占工作者进程，进程内最多3个执行协程。SQLite事务检查执行名额，防止重复领取和超发；工作者锁继续阻止重复进程。仅持有锁的工作者恢复中断任务，API重启不重发模型调用。

发布先构建和隔离检查，队列空闲后备份数据库，再切换中文版服务。冒烟检查同时验证匿名请求被拒绝、新空间列表为空、公开样例正常，不修改用户作品或调用模型。

有私有记录后不能回退到隔离前的程序，否则旧程序会重新公开数据。发布器发现上版没有隔离支持且已出现私有记录，会拒绝这种自动回退，保持数据与新release并停服等待维护；可以修复后发布隔离版。回退到同样支持隔离的版本可沿用原程序回滚方式，不用旧SQLite覆盖新作品。

## 验证边界

离线测试覆盖请求峰值3、第4个等待、同Key预算共享、单用户用满空位、多用户调度、章节顺序、停止继续、限流冷却、两个浏览器越权、伪造身份、跨站写入、幂等命名空间及旧稿一次性恢复。使用临时数据库和模拟模型，没有额外付费调用。生产浏览器交互、长期负载和长篇生成质量仍需另行验收。
